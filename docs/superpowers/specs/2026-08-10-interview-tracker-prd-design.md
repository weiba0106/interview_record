## 1. 产品概述

面试记录平台是一款面向秋招和日常实习求职者的个人效率工具。注册用户可以集中管理公司、岗位、投递进度、多轮面试经验、日程与提醒，并通过统计数据了解求职进展。用户数据默认私有；当用户希望交流经验时，可以选择具体内容生成只读分享链接。

产品采用多用户模式。任何人都可以使用邮箱注册账号，但每名用户只能访问和管理自己的公司、岗位、面试、日程和设置数据。

## 2. 背景与问题

求职记录通常散落在表格、备忘录、聊天记录和日历中，主要存在以下问题：

- 同一家公司可能投递多个岗位，普通表格难以清楚表达公司、岗位和多轮面试之间的关系。
- 投递状态不断变化，固定状态无法适配不同公司的招聘流程。
- 面试题、个人回答和复盘笔记缺少统一结构，后续检索和复习困难。
- 笔试、面试、投递截止和 Offer 截止时间分散，容易遗漏。
- 私人复盘和可分享经验混在一起，用户难以安全地对外分享部分内容。

## 3. 产品目标

### 3.1 V1 目标

1. 让用户在一个系统中完成从投递到 Offer 或流程结束的全过程记录。
2. 清晰支持“一个公司对应多个岗位、一个岗位对应多轮面试”的数据关系。
3. 通过可自定义的有序状态和高密度表格，提升岗位更新、搜索与筛选效率。
4. 通过日程、紧急程度和邮件提醒，降低错过关键节点的概率。
5. 在默认私有的前提下，允许用户安全、可撤销地分享指定面试内容。
6. 提供基础转化统计和完整数据导出，帮助用户复盘并保留自己的数据。

### 3.2 成功指标

V1 发布后，以以下指标衡量产品是否有效：

- 新用户完成注册后，首次创建公司和岗位的成功率不低于 85%。
- 已创建岗位的活跃用户中，至少 60% 创建过一条面试或日程记录。
- 日程提醒任务按计划进入邮件队列的成功率不低于 99%。
- 分享链接不存在跨用户越权读取，自动化权限测试通过率为 100%。
- 核心页面在桌面端和手机浏览器的关键操作完成率不低于 95%。

### 3.3 V1 不包含

- 团队协作、多人共同编辑或组织空间。
- 面试经验公开社区、评论、点赞、搜索公开内容或内容审核系统。
- 原生 iOS、Android 应用。
- 微信、GitHub 等第三方登录以及手机号验证码登录。
- Google Calendar、Outlook Calendar 等外部日历双向同步。
- 简历文件、录音、图片等附件上传。
- AI 面试分析、题目生成或自动总结。
- 历史数据导入；V1 仅提供导出。
- 分享链接密码保护和访问者统计。

## 4. 目标用户

### 4.1 核心用户

- 正在参加秋招、春招、暑期实习或日常实习的学生和应届生。
- 同时投递多个公司、多个岗位，需要频繁更新进度的求职者。
- 希望结构化沉淀面试题、回答和复盘，并在必要时分享部分经验的用户。

### 4.2 核心使用场景

1. 用户投递一个新岗位后，快速创建公司和岗位记录并保存投递链接。
2. 用户收到笔试或面试通知后，新增日程并设置邮件提醒。
3. 用户完成一轮面试后，记录面试题、个人回答和富文本复盘。
4. 用户在工作台通过搜索、筛选和状态更新管理全部岗位。
5. 用户选择指定轮次和字段生成只读链接，与同学分享面试经验。
6. 用户查看投递、面试和 Offer 转化情况，或导出全部个人数据。

## 6. 信息架构与页面

### 6.1 未登录页面

- 注册页
- 邮箱验证结果页
- 登录页
- 忘记密码页
- 重置密码页
- 分享链接只读页

### 6.2 登录后导航

- **工作台**：核心指标、岗位表格、即将到来的日程。
- **公司**：公司列表、公司详情及其全部岗位。
- **日程**：月历/列表视图、日程新增编辑、完成和取消。
- **统计**：状态分布、投递转化、面试结果和趋势。
- **设置**：账号、默认提醒、状态、招聘类型、主题、导出和账号删除。

桌面端使用左侧导航；移动端使用折叠菜单或底部导航。移动端工作台先显示紧急日程和核心指标，再显示可横向滚动或转换为卡片的岗位表格。

## 7. 功能需求

### 7.1 注册、登录与账号

#### 7.1.1 注册

- 用户使用邮箱和密码注册。
- 邮箱在系统内唯一，比较时忽略大小写并去除首尾空格。
- 密码至少 8 个字符，必须同时包含字母和数字。
- 注册后发送一次性验证链接，验证链接 24 小时内有效且使用后失效。
- 用户完成邮箱验证后方可登录。
- 支持在 60 秒冷却后重新发送验证邮件；同一邮箱和同一 IP 每小时最多各发送 5 次。

#### 7.1.2 登录与会话

- 支持邮箱密码登录、主动退出和登录过期后重新认证。
- 登录失败提示不暴露邮箱是否已注册。
- 同一邮箱与 IP 组合在 15 分钟内登录失败达到 10 次后，暂停尝试 15 分钟。
- 用户会话使用安全、HttpOnly、SameSite Cookie；生产环境必须启用 HTTPS。

#### 7.1.3 忘记密码

- 用户提交邮箱后，系统统一提示“如账号存在将发送邮件”。
- 重置链接一次性使用，1 小时后失效。
- 重置密码成功后，旧的活跃会话全部失效。

#### 7.1.4 账号设置

- 用户可以修改显示名称、时区和默认邮件提醒。
- 默认时区根据浏览器推断，无法推断时使用 Asia/Shanghai；用户可手动修改。
- 用户可以导出数据后删除账号。删除账号需要再次输入密码确认，随后不可恢复地删除该用户的业务数据和未过期分享链接。

### 7.2 公司管理

- 用户可以新增、查看、编辑和删除公司。
- 公司必填字段为公司名称；可选字段为官网和备注。
- 同一用户新增同名公司时系统提示可能重复，但允许用户确认后继续创建。
- 公司详情展示该公司下的全部岗位及各岗位当前状态。
- 公司存在关联岗位时，不允许直接删除；用户必须先将岗位迁移至其他公司或确认删除公司及其全部关联岗位。级联删除前明确展示将删除的岗位、面试、日程和分享数量。
- 不同用户可以创建同名公司，彼此数据完全独立。

### 7.3 岗位管理

#### 7.3.1 岗位字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 所属公司 | 是 | 一个岗位只能属于一个公司 |
| 职位名称 | 是 | 最长 100 个字符 |
| 招聘类型 | 是 | 默认提供“秋招”“日常实习”，用户可新增、改名和停用类型 |
| 当前状态 | 是 | 从用户自己的有序状态列表中选择 |
| 投递链接 | 否 | 仅接受 `http://` 或 `https://` 地址 |
| 投递日期 | 否 | 用于投递统计 |
| 截止时间 | 否 | 可同步创建“投递截止”日程 |
| 工作地点 | 否 | 自由文本，最长 100 个字符 |
| 岗位描述/备注 | 否 | 富文本，保存岗位要求及个人备注 |

- 不建立独立的“求职项目/批次”。秋招、日常实习等直接作为岗位的招聘类型。
- 新增岗位时可以搜索已有公司，也可以在同一表单中快速创建公司。
- 用户可以查看、编辑、归档和删除岗位。
- 归档岗位默认不出现在工作台，但仍参与历史统计，且可以恢复。
- 删除岗位会同时删除其面试轮次、题目、关联日程和分享链接；删除前必须二次确认。

#### 7.3.2 岗位表格

- 默认列：公司、职位、招聘类型、当前状态、投递日期、下次日程。
- 支持按公司或职位关键词搜索。
- 支持按招聘类型、状态、日期范围和是否归档筛选。
- 支持按最近更新、投递日期、下次日程排序。
- 点击状态可就地更改；点击行进入岗位详情。
- 默认每页 20 条，支持分页。用户的筛选条件在当前会话内保留。

### 7.4 状态管理

#### 7.4.1 默认状态

每个新用户注册时创建一套属于该用户的默认状态副本：

1. 待投递
2. 已投递
3. 简历筛选中
4. 笔试/测评中
5. 面试中
6. Offer
7. 未通过
8. 已放弃

#### 7.4.2 自定义规则

- 用户可以新增、改名、调整顺序和设置颜色，也可以将状态停用。
- 每个状态必须映射到一个统计分类：进行中、成功、未通过或放弃。
- 默认状态也可修改，因为注册后它们是用户自己的状态副本。
- 正在被岗位使用的状态不能直接删除；用户必须先将关联岗位批量迁移到另一个状态。
- 状态顺序决定设置页展示顺序和状态筛选顺序。
- V1 的主工作台采用表格，不要求拖拽看板。

### 7.5 多轮面试记录

#### 7.5.1 数据关系

- 一个岗位可以包含零到多轮面试。
- 每轮面试只能属于一个岗位，并通过岗位关联到公司。
- 轮次默认按时间升序排列；时间为空时按用户设置的轮次序号排列。

#### 7.5.2 面试轮次字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 轮次名称 | 是 | 例如“一面”“技术二面”“HR 面” |
| 轮次序号 | 是 | 正整数，同一岗位内不可重复 |
| 面试类型 | 是 | 电话、视频、现场、笔试/测评、其他 |
| 开始与结束时间 | 否 | 填写后可同步创建日程 |
| 面试结果 | 是 | 待进行、待结果、通过、未通过、取消 |
| 面试题与回答 | 否 | 可添加多条，每条包含题目、个人回答和可选分类 |
| 过程记录 | 否 | 富文本，记录面试流程和交流内容 |
| 复盘总结 | 否 | 富文本，记录表现、反馈和改进项 |

- 用户可新增、编辑、删除和调整轮次顺序。
- 改变轮次结果不会未经确认自动修改岗位状态；系统可以提示用户是否同步更新。
- 富文本需进行服务端安全清洗，不允许脚本、事件属性和危险链接协议。

### 7.6 日程与紧急程度

#### 7.6.1 日程类型

- 投递截止
- 笔试/测评
- 面试
- HR 沟通
- Offer 截止
- 其他

#### 7.6.2 日程字段

- 标题、类型、开始时间或截止时间为必填项。
- 可选关联一个岗位；面试日程还可选关联一个具体面试轮次。
- 可填写结束时间、地点/会议链接、备注和完成状态。
- 日程状态包括待处理、已完成和已取消。
- 面试轮次时间和关联日程双向同步；修改任一方时必须保持一致。

#### 7.6.3 紧急程度

系统按用户时区和日程开始/截止时间自动计算：

| 等级 | 自动规则 | 视觉表达 |
| --- | --- | --- |
| 紧急 | 已逾期且未完成，或剩余时间少于 24 小时 | 红色、警告图标、“紧急”文字和剩余时间 |
| 临近 | 剩余 24 小时至不足 72 小时 | 橙色、时钟图标、“临近”文字和剩余时间 |
| 普通 | 剩余时间不少于 72 小时 | 蓝色、圆点图标、“普通”文字和剩余时间 |
| 已处理 | 已完成或已取消 | 灰色、完成/取消图标和状态文字 |

- 用户可将待处理日程手动覆盖为紧急、临近或普通；手动值优先于自动值。
- 用户清除手动覆盖后，系统恢复自动计算。
- 颜色不是唯一信息载体，所有场景必须同时显示图标或文字标签。

#### 7.6.4 工作台日程

- 工作台右侧展示未来 7 天内最近的 5 条待处理日程，按紧急程度和时间排序。
- 已逾期且未完成的日程固定显示在列表顶部。
- 用户可以从工作台直接进入日程详情、标记完成或新增日程。
- 移动端将日程模块放在岗位表格上方。

### 7.7 邮件提醒

- 只有已验证邮箱的账号可以启用邮件提醒。
- 面试类日程默认在 24 小时前和 2 小时前提醒。
- 投递、测评和 Offer 截止类日程默认在 24 小时前和 2 小时前提醒。
- 用户可在设置中修改默认规则，并在单条日程中增加、修改或关闭提醒。
- 支持同一日程设置多个提醒时间，但同一提醒不得重复发送。
- 修改或取消日程后，尚未发送的提醒同步更新或取消。
- 邮件发送失败后自动重试，最多 3 次；仍失败时在应用内显示失败状态，但不阻塞日程使用。
- 邮件中包含日程标题、公司、岗位、时间和返回系统的链接，不包含面试问题、回答或私人复盘正文。

### 7.8 只读分享链接

#### 7.8.1 分享范围

- 分享入口位于岗位详情。
- 用户可以勾选是否展示公司名称、职位名称、招聘类型和当前状态。
- 用户可以从该岗位的面试轮次中选择零到多轮进行分享。
- 每个已选轮次可以进一步选择展示基础信息、面试题、个人回答、过程记录、复盘总结和结果。
- 投递链接、岗位私人备注、日程、提醒设置和账号信息默认不可分享，也不提供勾选入口。

#### 7.8.2 链接规则

- 系统生成不可枚举的随机令牌，访问者无需登录即可查看。
- 用户可选择 1 天、7 天、30 天或永久有效。
- 用户可以随时关闭链接；关闭或到期后访问统一显示“链接已失效”。
- 分享内容为实时视图：原记录被编辑后，链接展示同步更新，但可见字段和轮次仍以创建链接时的选择为准。
- 原岗位或账号被删除后，相关链接立即失效。
- 分享页添加 `noindex`，禁止搜索引擎收录，并隐藏所有编辑入口。
- V1 不展示浏览次数和访问者信息。

### 7.9 统计与概览

#### 7.9.1 工作台指标

- 全部未归档岗位数
- 当前统计分类为“进行中”的岗位数
- 未来 7 天待处理日程数
- 当前统计分类为“成功”的 Offer 岗位数

#### 7.9.2 统计页

- 按状态展示岗位数量和占比。
- 按招聘类型展示投递、面试和 Offer 数量。
- 展示指定时间范围内的投递趋势和面试轮次数量。
- 展示以下转化率：
  - 面试触达率 = 至少有一轮面试的岗位数 ÷ 已填写投递日期的岗位数。
  - Offer 转化率 = 统计分类为“成功”的岗位数 ÷ 已填写投递日期的岗位数。
  - 面试轮次通过率 = 结果为“通过”的轮次数 ÷ 结果为“通过”或“未通过”的轮次数。
- 分母为零时显示“暂无数据”，不显示 0%。
- 支持按投递日期范围和招聘类型筛选；所有指标使用同一筛选条件。

### 7.10 数据导出

- 用户可从设置页手动发起导出。
- **CSV 导出**生成一个 ZIP 包，至少包含 `companies.csv`、`positions.csv`、`interview_rounds.csv`、`interview_questions.csv`、`schedules.csv` 和 `statuses.csv`。
- **JSON 导出**生成一份包含公司、岗位、状态、面试、日程、提醒配置和用户偏好的完整结构化备份。
- 导出不包含密码散列、会话、邮箱验证令牌、密码重置令牌和邮件服务内部信息。
- 导出时间统一使用 ISO 8601 格式并带时区。
- 单个用户数据量不超过 10,000 个岗位时，应在页面内完成生成并提供一次性下载；下载地址 30 分钟后失效。
- 导出文件名包含生成日期。CSV 使用 UTF-8 BOM，保证中文在常见表格软件中正常显示。

### 7.11 主题与视觉规范

系统内置四套完整主题：

1. 原始靛蓝
2. 森林青绿
3. 暖杏棕
4. 石墨灰 + 珊瑚红

- 新用户默认使用“石墨灰 + 珊瑚红”。
- 用户可在设置中切换主题，切换后立即生效并保存到账号偏好；登录其他设备后继续使用同一主题。
- 四套主题必须覆盖导航、按钮、链接、焦点态、表格、筛选器、卡片和空状态，不只是替换主按钮颜色。
- 紧急程度使用统一的语义色，不随主题改变含义；主题需为语义色提供可读背景。
- 正文和关键操作的颜色对比度需达到 WCAG 2.1 AA。

## 8. 核心用户流程

### 8.1 首次使用

1. 用户提交邮箱和密码。
2. 系统发送验证邮件。
3. 用户完成验证并登录。
4. 系统为用户创建默认状态、默认招聘类型、默认提醒和默认主题。
5. 空状态引导用户创建第一家公司和岗位。

### 8.2 新增岗位

1. 用户在工作台点击“新增岗位”。
2. 用户选择已有公司或快速创建公司。
3. 用户填写职位、招聘类型、状态和可选投递信息。
4. 若填写截止时间，用户可确认同步创建日程与提醒。
5. 保存成功后，岗位立即出现在表格中。

### 8.3 记录一轮面试

1. 用户进入岗位详情并点击“新增面试轮次”。
2. 用户填写轮次名称、类型、时间和结果。
3. 用户添加多条面试题与回答，并填写过程和复盘。
4. 若填写时间，系统提示同步创建面试日程。
5. 保存后，岗位详情按轮次顺序展示；系统可提示是否更新岗位状态。

### 8.4 分享面试经验

1. 用户在岗位详情点击“分享”。
2. 用户选择岗位字段、面试轮次和每轮可见内容。
3. 用户预览分享页面并选择有效期。
4. 系统生成只读链接。
5. 用户可以复制链接，之后也可在岗位详情关闭或重新配置分享。

## 9. 数据模型概览

| 实体 | 关键关系与职责 |
| --- | --- |
| User | 账号主体，拥有全部业务数据 |
| UserPreference | 一对一保存时区、主题和默认提醒设置 |
| Company | 属于一个用户，一家公司包含多个岗位 |
| JobType | 属于一个用户，供岗位选择秋招、日常实习或自定义类型 |
| PositionStatus | 属于一个用户，保存顺序、颜色、启用状态和统计分类 |
| Position | 属于一个用户和一个公司，关联招聘类型和当前状态 |
| InterviewRound | 属于一个岗位，保存结构化轮次信息和富文本记录 |
| InterviewQuestion | 属于一个面试轮次，保存题目、回答和分类 |
| ScheduleEvent | 属于一个用户，可选关联岗位和面试轮次 |
| Reminder | 属于一个日程，保存提醒时间、状态和发送结果 |
| ShareLink | 属于一个用户和岗位，保存令牌摘要、有效期、可见字段和已选轮次 |

所有业务表必须直接或可验证地关联 `user_id`。服务端查询不得仅依赖前端传入的资源 ID，必须同时校验资源归属。

## 10. 系统设计边界

系统按以下职责划分，具体技术栈在实施计划中确定：

- **响应式 Web 前端**：页面展示、表单校验、主题切换和移动端适配。
- **应用服务**：认证、公司岗位、状态、面试、日程、分享、统计与导出 API。
- **MySQL**：存储账号、业务实体、用户偏好和分享配置；使用外键保证关系一致。
- **后台任务**：扫描待发送提醒、生成邮件任务、失败重试和清理过期令牌/导出文件。
- **邮件服务**：发送验证、重置密码和日程提醒邮件。

富文本以经过服务端白名单清洗的 HTML 存入 MySQL `LONGTEXT` 字段；每次写入都重新清洗，并在输出时执行安全编码以阻止 XSS。

## 11. 权限、安全与隐私

- 除公开分享接口外，所有业务接口必须要求登录。
- 用户只能读取和修改 `user_id` 与当前账号一致的数据。
- 密码必须使用适合密码存储的强哈希算法处理，不得明文或可逆加密保存。
- 邮箱验证令牌、重置令牌和分享令牌不得以明文直接存入数据库；服务端保存不可逆摘要。
- 登录、注册、重发邮件、重置密码和分享访问需配置速率限制。
- 所有富文本输出前完成清洗和编码，所有外部链接使用安全协议并避免 opener 劫持。
- 关键删除操作必须二次确认；账号删除需要重新验证密码。
- 日志不得记录密码、完整令牌、面试回答或富文本复盘正文。

## 12. 异常与边界处理

- **重复公司**：提示相似记录，用户可选择已有公司或确认继续新增。
- **无效投递链接**：前端即时提示，服务端再次校验，只允许 HTTP(S)。
- **删除已使用状态**：阻止删除并要求迁移关联岗位。
- **日程时间变化**：取消未发送的旧提醒，按新时间重新计算。
- **提醒发送失败**：自动重试并显示失败状态，不重复发送已成功提醒。
- **分享过期或关闭**：统一返回失效页，不暴露岗位是否存在。
- **统计数据不足**：显示“暂无数据”，并解释计算所需字段。
- **并发编辑**：后端使用更新时间或版本号检测冲突；检测到冲突时提示刷新，不静默覆盖较新的内容。
- **网络中断**：表单保留未提交内容到当前浏览器会话，并提供重试；不得显示伪成功状态。

## 13. 非功能需求

### 13.1 性能

- 在单用户不超过 10,000 个岗位、每个岗位不超过 20 轮面试的设计容量内，分页列表和筛选接口 P95 响应时间不超过 500 ms，不含网络传输。
- 常用统计结果的缓存时长不得超过 60 秒；用户修改相关数据后，对应缓存应在 5 秒内主动失效。
- 邮件提醒任务应在计划时间后 1 分钟内进入邮件发送队列。

### 13.2 可用性与兼容性

- 支持最近两个稳定版本的 Chrome、Edge、Safari 和 Firefox。
- 支持 375 px 及以上宽度；桌面端以 1280–1440 px 为主要设计宽度。
- 所有关键操作支持键盘访问；表单错误与状态标签可被辅助技术识别。
- 日期时间按用户时区展示，服务端统一保存为 UTC 时间。

### 13.3 可观测性

- 记录 API 错误率、登录失败率、邮件队列积压、提醒失败数和导出失败数。
- 后台任务使用稳定任务 ID，保证提醒和导出任务可追踪、可去重。

## 14. 验收标准

### 14.1 账号与隔离

- 使用两个测试账号创建同名公司和岗位时，任一账号均无法通过页面或直接 API 访问另一个账号的数据。
- 未验证邮箱无法登录；验证、登录、退出和重置密码流程均可完成。

### 14.2 公司、岗位与状态

- 一个公司可成功创建至少两个岗位，每个岗位可独立维护状态和投递链接。
- 新用户拥有完整默认状态；自定义状态可以新增、改名、排序、改色和映射统计分类。
- 正在使用的状态无法直接删除，完成迁移后可以删除。
- 工作台可按关键词、招聘类型、状态和日期筛选岗位。

### 14.3 面试记录

- 一个岗位可以创建至少三轮面试，并按轮次顺序展示。
- 每轮可保存多个题目与回答，以及过程和复盘富文本。
- 危险脚本和事件属性无法通过富文本保存或展示。

### 14.4 日程与提醒

- 日程在剩余时间跨越 72 小时和 24 小时边界时自动更新紧急程度。
- 用户手动覆盖紧急程度后自动规则不再覆盖；清除手动值后恢复自动规则。
- 颜色、图标、文字等级和剩余时间同时显示。
- 修改、完成或取消日程后，未发送提醒正确更新或取消；同一提醒不会重复发送。

### 14.5 分享、统计和导出

- 用户可选择不同轮次和字段生成链接，访问者只能看到已选择内容。
- 分享链接到期、关闭或源岗位删除后立即失效。
- 三项转化率按本文定义的分子和分母计算，分母为零时显示“暂无数据”。
- CSV ZIP 和 JSON 均可下载，中文无乱码，且不包含密码、令牌和会话信息。

### 14.6 主题与响应式体验

- 四套主题均可切换，刷新页面和更换设备登录后仍保留用户选择。
- 新用户默认使用石墨灰 + 珊瑚红。
- 375 px 宽度下能够完成新增岗位、更新状态、查看日程和记录面试。
- 紧急程度语义在四套主题中保持一致，并达到可读对比度。

## 15. V1 实施与验收顺序建议

1. 账号、权限隔离和用户默认数据。
2. 公司、岗位、招聘类型和状态管理。
3. 多轮面试记录及富文本安全处理。
4. 日程、紧急程度、后台任务和邮件提醒。
5. 工作台、筛选、统计和响应式适配。
6. 选择性分享、数据导出和四套主题。
7. 全链路权限、安全、性能和浏览器兼容验收。

此顺序只用于降低开发依赖风险；上述七项全部通过后，V1 才视为达到发布条件。
